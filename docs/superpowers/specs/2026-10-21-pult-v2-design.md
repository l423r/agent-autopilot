# Пульт v2: картинки, проекты в чате, подсказка ответа, лимиты, все проекты и переключение

Дата: 2026-10-21. Продолжение `docs/plans/2026-10-21-web-panel.md` (пульт v1 работает на `https://151-243-245-85.sslip.io/pult/`).

## Зачем

Пользователь управляет сервером только с телефона через пульт. На практике упёрся в пять вещей:

1. Нельзя показать планировщику, что он видит (скриншот ошибки, фото, картинку из галереи).
2. В чате непонятно, о каком проекте речь, — приходится объяснять словами; а в одном сообщении бывают задания для разных проектов.
3. В Claude Code нравилась подсказка ответа: вероятный ответ подставлялся в поле ввода и отправлялся одним нажатием.
4. Не видно, сколько осталось лимитов Claude (5-часового и недельного).
5. Вкладка «План» показывает только один проект; переключить автопилот на другой проект/план можно только через чат.

Успех: всё это делается с телефона в пульте, без терминала и без объяснений планировщику «где что лежит».

## Цели

### 1. Картинки в чате
- Кнопка-скрепка рядом с полем ввода → стандартный выбор файла телефона (камера / галерея / файлы), только изображения (`accept="image/*"`), можно несколько за раз (решение исполнителя: до 5).
- Перед отправкой — миниатюры над полем ввода с крестиком удаления.
- Картинка уменьшается в браузере (длинная сторона ~2000 px, JPEG) — фото с телефона весят мегабайты, а мобильный интернет у пользователя ограничен.
- Сервер сохраняет файл в `<stateDir>/web/uploads/` и добавляет к тексту сообщения для планировщика путь к файлу; планировщик открывает его инструментом Read (Claude Code читает изображения). Сообщение может быть и без текста — только картинка.
- В истории чата у сообщения пользователя видны миниатюры (раздаются сервером пульта по относительному пути, под тем же паролем Caddy).
- Хранение: старые загрузки удаляются вместе с «Новый разговор»; плюс разумный предел (решение исполнителя, напр. последние 200 файлов / 200 МБ).

### 2. Проекты через `@` в чате
- Набор `@` в поле ввода открывает над клавиатурой список проектов; тап вставляет `@имя `. Список фильтруется по мере ввода после `@`.
- Список проектов — все проекты из конфигов автопилота (тот же источник, что в п. 5). Короткое имя — из нового поля `name` проекта, по умолчанию — имя папки `projectDir` (сейчас: `agent-autopilot`, `sigaret-counter`; короткие `autopilot`, `sigaret` — решение планировщика, пользователь согласился).
- В одном сообщении можно упомянуть несколько проектов.
- Сервер перед отправкой планировщику дописывает к сообщению служебный блок: для каждого упомянутого проекта — `projectDir`, текущий `planPath`, `progressPath`, и активен ли он сейчас у автопилота. Пользователь этот блок в чате не видит; в истории хранится то, что он написал.
- Упоминания в тексте сообщения в чате подсвечиваются.

### 3. Подсказка ответа
- Планировщик заканчивает каждый ответ скрытой строкой с самым вероятным коротким ответом пользователя (формат — решение исполнителя, напр. `<!-- suggest: Да, запускай -->` последней строкой). Правило добавляется в `web/planner-prompt.md`.
- Пульт вырезает эту строку из показа и из истории-отображения, а текст подсказки показывает серым placeholder'ом в поле ввода и кнопкой «↵ <текст>» рядом/над полем.
- Тап по кнопке отправляет подсказку как сообщение. Если пользователь начинает печатать — подсказка скрывается. Подсказка есть только у последнего ответа; без строки — подсказки нет.
- Никаких дополнительных запросов к Claude.

### 4. Лимиты Claude
- Пункт «Лимиты» в меню (⋮). Показывает два блока: «5 часов» и «Неделя» — полоска с процентом использования и время сброса (по местному времени телефона, «сегодня 20:20» / «28.10 06:00»).
- Источник: `GET https://api.anthropic.com/api/oauth/usage` с `Authorization: Bearer <claudeAiOauth.accessToken из /root/.claude/.credentials.json>` и `anthropic-beta: oauth-2025-04-20`; поля `five_hour` и `seven_day` (`utilization` в процентах, `resets_at`). Проверено 2026-10-21 — работает. Эндпоинт недокументированный.
- Запрос делает сервер пульта (токен в браузер не уходит), при открытии пункта меню; кеш на сервере ~60 с.
- Любая ошибка (нет файла, 401, другой формат) → «Нет данных о лимитах» с кратким пояснением; остальной пульт не затрагивается. Токен не обновлять самому и в логи не писать.

### 5. Вкладка «План»: все проекты и переключение автопилота
- Вкладка показывает карточки всех проектов. На карточке: имя, текущий план (имя файла) с полосой прогресса; у проекта, над которым работает автопилот, — метка «в работе» и статус автопилота (работает / пауза / ждёт тебя / готово / застрял).
- Тап по карточке раскрывает задачи текущего плана с галочками (как сейчас во вкладке), ниже — список остальных планов проекта (все `.md` в папке плана, кроме файлов прогресса) с прогрессом; каждый раскрывается так же.
- У каждого незавершённого плана — кнопка «Запустить». После подтверждения («Переключить автопилот на <проект> / <план>?») автопилот переходит на этот план и выполняет его.
  - Если автопилот в этот момент выполняет задачу — текущая задача не обрывается: переключение происходит после её завершения; пульт показывает «Переключится после текущей задачи».
  - Если автопилот остановлен (`done` / `paused` / `waiting-user` / `halted`) — переключение сразу, автопилот запускается на новом плане.
  - У выполненных планов кнопки нет.
- Для нового плана нужен файл прогресса: если у плана его нет, создаётся рядом по существующему соглашению проекта (решение исполнителя; в agent-autopilot — `<план>.progress.md`).

### 0. Отложенные замечания ревью v1 (делаются первыми)
Отдельный план доработок отменён (пользователь согласился); его 8 пунктов — первые задачи этого плана, т.к. правят те же файлы. Источник — строки `minor (отложено)` в `docs/plans/2026-10-21-web-panel.progress.md`:

- после перезапуска сервера посреди ответа в истории появляется запись «Ответ прерван перезапуском»;

- `/api/history` ограничен по байтам (~1 МБ свежих записей);
- `` [`код`](https://…) `` в Markdown — без NUL-заглушки;
- `setup-web.sh`: при провале `caddy validate` восстанавливает Caddyfile из копии; без строки `terminal` в ntfy-credentials — понятная ошибка.

## Как будет исполняться

- План выполняет сам автопилот на своём же репозитории (так же был сделан v1). Поэтому каждый шаг безопасен для работающего демона: новый код читает и старый формат `config.json`/`state.json`, пока миграция не выполнена; миграция конфигов — отдельная задача; перезапуск служб `agent-autopilot` и `agent-autopilot-web` — только между задачами или в ручной задаче в конце (проверка с телефона).
- «Выполненный план» = все чекбоксы задач отмечены (старый `2026-10-20-autopilot.md` отмечен 2026-10-21 по согласию пользователя). Файлы прогресса (`*.progress.md`, `progress.md`) в список планов не входят.
- Переключение, пока автопилот ждёт сброса лимита, — сразу (решение планировщика); счётчики попыток при смене плана сбрасываются.

## Ограничения

- Всё из Global Constraints плана v1 остаётся: сервер на `127.0.0.1`, авторизация только Caddy, без runtime-npm-зависимостей, экранирование HTML до Markdown, один ответ планировщика одновременно, русский интерфейс, тёмная тема, 360–430 px, кнопки ≥44 px.
- Сейчас конфиги — отдельные файлы `config.json` (активный, со всеми ntfy-настройками, `stateDir: state-web`) и `config.sigaret.json` (устаревшая копия с другим проектом и другим `stateDir`). Нужен один источник: общие настройки + список проектов + какой проект/план активен. Как именно хранить — решение исполнителя, но:
  - `node autopilot.mjs status/resume/...`, служба `agent-autopilot` и `AUTOPILOT_CONFIG` продолжают работать;
  - переключение не теряет состояние и счётчики другого проекта и не путает журнал прогресса;
  - в планировщике (`web/planner-prompt.md`) и README описано, где теперь список проектов и как переключать.
- Переключение исполняет демон автопилота (как пауза/продолжить — через канал команд или общий файл состояния; решение исполнителя), пульт не останавливает процессы Claude сам.
- Загруженные картинки и токен лимитов не попадают в git и в ntfy.
- Безопасность — соразмерная: загрузка только изображений, предел размера запроса, имена файлов генерирует сервер.

## Не цели

- Другие типы файлов (документы, архивы, видео).
- Несколько проектов одновременно у автопилота — по-прежнему один активный.
- Редактирование планов кнопками в пульте (меняет планировщик через чат).
- Автоматическое обновление лимитов в реальном времени, графики расхода.

## Анти-цели (провал, даже если формально работает)

- Переключение обрывает задачу на середине или автопилот начинает выполнять не тот план.
- Пульт перестаёт работать целиком, когда эндпоинт лимитов сломался.
- Подсказка отправляется сама, без нажатия, или служебная строка/служебный блок `@` видны в чате.
- Фото с телефона грузится минутами из-за размера.

## Что оставлено исполнителю

Формат хранения проектов и активного выбора, механизм передачи «переключить» демону, формат строки подсказки, пределы хранения загрузок, точная вёрстка (в стиле v1). Проверка — скриншоты всех новых экранов (`scripts/web-screenshots.mjs`) и ревью свежим ревьюером, как в v1.
