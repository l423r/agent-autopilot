# Пульт автопилота в браузере — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** С телефона через браузер: разговаривать с отдельной сессией Claude-планировщика (она читает и меняет планы), смотреть план с галочками и статус автопилота, ставить его на паузу и продолжать.

**Architecture:** Отдельный процесс `web/server.mjs` (Node, без зависимостей) на `127.0.0.1:7690`, наружу его отдаёт Caddy по пути `/pult/` с тем же паролем, что у веб-терминала. Чат — это `claude -p` с `--resume <sessionId>` и `--output-format stream-json`: каждое сообщение продолжает одну сессию планировщика, ответ потоком идёт в браузер (SSE). Команды пауза/продолжить пульт не выполняет сам, а публикует в канал команд ntfy — их исполняет демон автопилота по уже проверенному пути. Страница — один HTML-файл с ванильным JS, тёмная тема, под ширину телефона.

**Tech Stack:** Node 22 (`node:http`, `child_process`, `fetch`), ванильный HTML/CSS/JS; тесты `node:test`; скриншоты — `playwright-core` + `/usr/bin/chromium` (devDependency только для скрипта проверки).

**Spec:** договорённость в чате 2026-10-21 («пульт следующим»): чат с отдельной сессией-планировщиком, вкладки «План» и «Статус» с кнопками, ntfy остаётся для push-уведомлений и ведёт в пульт.

## Global Constraints

- Сервер слушает только `127.0.0.1:7690`; аутентификация — basicauth в Caddy (в самом сервере её нет). Все пути сервера — относительно префикса `/pult/` (Caddy убирает префикс через `handle_path`); в HTML все ссылки относительные.
- Без npm-зависимостей в рантайме. Тесты — `npm test`; `playwright-core` — только devDependency для `scripts/web-screenshots.mjs`.
- Планировщик запускается как `claude -p <текст> --output-format stream-json --verbose --permission-mode dontAsk --settings <autopilotDir>/claude-settings.json --append-system-prompt <web/planner-prompt.md>` с `cwd: /root`, плюс `--resume <sessionId>`, если сессия уже есть. Бинарник берётся из `AUTOPILOT_CLAUDE` (по умолчанию `claude`) — так тесты подставляют поддельный.
- Одновременно идёт не больше одного ответа планировщика; новое сообщение во время ответа → 409. Кнопка «Стоп» убивает группу процессов ответа (SIGTERM, через 10 с SIGKILL).
- Состояние пульта — `<stateDir>/web/`: `session.json` (`{ sessionId }`), `history.jsonl` (по строке `{ role: 'user'|'assistant'|'error', text, at }`). «Новый разговор» очищает оба.
- Пауза/продолжить — POST в `<ntfyServer>/<ntfyTopic>-cmd` с `Authorization: Bearer <ntfyCommandToken>` и телом `пауза`/`продолжить`; статус пульт читает сам из `state.json` и плана (без ntfy).
- Ответы Claude рендерятся как простой Markdown (заголовки, жирный, курсив, списки, `код`, блоки кода, ссылки) строго после экранирования HTML; никакого `innerHTML` с неэкранированным текстом.
- Интерфейс по-русски, тёмная тема (фон `#14121f`, акцент `#7b3cff`), вёрстка под 360–430 px, без горизонтальной прокрутки, крупные кнопки (≥44 px).
- Уведомления ntfy получают `click=<publicUrl>` (новый ключ конфига `webPublicUrl`, напр. `https://151-243-245-85.sslip.io/pult/`) — нажатие на уведомление открывает пульт.
- Автор коммитов — L423R.

## Review Focus

1. XSS: ответ Claude или текст плана с `<script>`, `<img onerror>`, `javascript:`-ссылкой не исполняется в браузере.
2. Обрыв SSE (телефон ушёл в фон) посреди ответа: процесс Claude не убивается, ответ дописывается в историю, при возвращении страница показывает его целиком.
3. Сессия Claude недоступна (`--resume` с несуществующим id, лимит, ошибка входа): понятное сообщение в чате, следующая попытка начинает новую сессию, сервер не падает.
4. Перезапуск сервера посреди ответа: «зависший» ответ не блокирует новые сообщения навсегда (флаг занятости не переживает рестарт; осиротевший процесс убит).
5. Очень длинный ответ или план (100+ КБ): страница не зависает, история не раздувается без предела (хранить последние 500 записей).

## Структура файлов

- `web/server.mjs` — HTTP-сервер: статика, API, SSE.
- `web/chat.mjs` — запуск планировщика, разбор `stream-json`, история, сессия.
- `web/markdown.mjs` — безопасный Markdown → HTML (используется и в браузере: отдаётся как модуль).
- `web/index.html` — страница пульта (вкладки Чат / План / Статус).
- `web/planner-prompt.md` — системная добавка для планировщика.
- `systemd/agent-autopilot-web.service`, `scripts/web-screenshots.mjs`, `scripts/setup-web.sh`.
- Тесты: `test/web-markdown.test.mjs`, `test/web-chat.test.mjs`, `test/web-server.test.mjs`; фикстура `test/fixtures/fake-claude-stream.mjs`.

### Task 3: HTTP-сервер и API

**Files:** Create `web/server.mjs`, `test/web-server.test.mjs`; Modify `config.example.json` (`webPort: 7690`, `webPublicUrl: ""`)

**Interfaces:**
- Consumes: Task 1–2; `parsePlan`, `loadState`, `statusText`.
- Produces: `startServer(cfg, { port, claudeBin }): Promise<{ port, close() }>`; запуск `node web/server.mjs` читает конфиг как `autopilot.mjs` (`AUTOPILOT_CONFIG`). Маршруты:
  - `GET /` → `index.html`; `GET /markdown.mjs` → модуль (`text/javascript`).
  - `GET /api/history` → `{ busy, entries }`.
  - `POST /api/chat` `{ text }` → 202 (или 409 при занятости, 400 при пустом/длиннее 20 000 символов).
  - `GET /api/events` → SSE: `delta`/`done`/`error`/`busy`; переподключившийся клиент получает текущее состояние (`busy` и накопленный текст ответа).
  - `POST /api/stop`, `POST /api/reset` (409 во время ответа).
  - `GET /api/plan` → `{ path, markdown, tasks, done, total }` для `planPath` из конфига.
  - `GET /api/status` → `{ text: statusText(...), state }`.
  - `POST /api/command` `{ cmd: 'pause'|'resume' }` → публикация в ntfy (см. Global Constraints), ответ `{ ok }`; иной `cmd` → 400.
- [x] **Step 1: Тесты** (сервер на порту 0, поддельные Claude и ntfy): все маршруты выше, включая 409/400; SSE получает delta и done; клиент отключается посреди `slow` → ответ всё равно в `/api/history`; переподключение во время `slow` → приходит накопленный текст; `/api/command` публикует `пауза` с Bearer-токеном; `/api/plan` отдаёт число задач; при старте сервер убивает осиротевший процесс ответа из `<stateDir>/web/child.pid` и не считается занятым.
