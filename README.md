# agent-autopilot

Служба, которая ведёт Claude Code по плану с галочками (формат superpowers: `### Task N: …` и шаги `- [ ]`) и не останавливается из-за лимитов.

Каждая итерация — свежий `claude -p` на одну задачу: прочитать план и журнал прогресса → сделать задачу по TDD → отметить галочки → закоммитить. Обрыв посередине безопасен: следующая итерация начнёт с последнего коммита.

## Что умеет

- **Лимиты.** Если Claude упёрся в лимит, автопилот берёт время сброса из сообщения и спит до него; если время не распознано — повторяет через `retryMinutes` (15 мин).
- **Запасная учётка.** При лимите основной задача продолжается на запасной учётке (см. «Запасная учётка»).
- **Падения и перезагрузки.** systemd перезапускает службу; осиротевший процесс `claude` убивается перед новым запуском.
- **Остановка по готовности.** Все галочки стоят → статус `done`, служба останавливается.
- **Защита от зацикливания.** Одна задача не удалась `maxAttempts` (3) раза подряд → `halted`.
- **Ручные задачи.** Задача с `[manual]` в заголовке → `waiting-user`, ждёт человека.
- **Задачи планировщика.** Задача с `[planner]` в заголовке (выкладка, правка конфига, проверка на живом сервере) выполняется сама: отдельный `claude -p` с ролью планировщика — промпт `web/planner-prompt.md` + `planner-task-prompt.md` (только шаги задачи, проверка каждого изменения, откат из шага при сбое). Модель без пометки — `opus`. Если нужен человек, исполнитель пишет в журнал проекта «НУЖЕН ЧЕЛОВЕК: …» и выходит без галочки — это неудачная попытка; после `maxAttempts` → `halted` с этим текстом в причине. Шаг `systemctl restart agent-autopilot` в `[planner]` запрещён: такая задача считается `[manual]` (предупреждение при разборе плана).
- **Авто-пуш (необязательно).** `"pushAfterTask": true` → после каждой выполненной задачи `git push` текущей ветки проекта в её upstream. Ошибка пуша только пишется в лог, автопилот продолжает; коммиты уйдут со следующим удачным пушем.
- **Уведомления на телефон (необязательно)** через [ntfy](https://ntfy.sh): `"ntfyTopic": "<секретное имя канала>"` (и `"ntfyServer"`, по умолчанию `https://ntfy.sh`; для своего сервера с закрытым доступом — `"ntfyToken": "tk_…"` с правом записи). Приходят при каждой остановке (готово, ручная задача, застрял, нужен вход, пауза) и при упоре в лимит со временем продолжения; `"notifyEachTask": true` — ещё и после каждой выполненной задачи. В приложении ntfy подпишитесь на тот же канал. Имя канала — как пароль: кто его знает, читает уведомления.
- **Паузы (необязательно).** `"pauseAfterPhase": true` → пауза после последней задачи каждого `## Этап …`.
- **Ошибка входа ≠ лимит.** Истёк логин → `auth`, служба останавливается.
- Тайм-аут итерации — `iterationTimeoutMinutes` (60).

## Установка

```bash
cd /root/agent-autopilot
cp config.example.json config.json   # поправить projectDir / planPath / progressPath и projects
bash install.sh                      # ставит и включает службу (не запускает)
echo 'EXPO_TOKEN=...' >> /root/.config/agent-autopilot.env   # если проекту нужны секреты
```

Проверочный запуск одной итерации: `node autopilot.mjs once`. Затем: `systemctl start agent-autopilot`.

## Требования к плану

Автопилот делает только то, что написано в плане, поэтому план обязан заканчиваться этапом проверки, который выполняет сам автопилот:

1. **Проверка результата глазами**: для приложения — скриншоты каждого экрана и состояния, просмотр и исправление дефектов.
2. **Ревью кода свежим ревьюером** (отдельный субагент, superpowers:requesting-code-review) на весь код; Critical/Important исправляются через TDD, Minor записываются в журнал.
3. **Финальный артефакт после исправлений** (например, APK), а не до них.

Шага `git push` в плане быть не должно: автопилот пушит сам после каждой задачи (`pushAfterTask`), а исполнителю пуш запрещён — такой шаг останавливает автопилот.

### Виды задач

- **`[planner]`** — выкладка тестированным скриптом с откатом, конфиг из уже известных данных, Bot API, проверки на живом сервере. Автопилот выполняет такую задачу сам (см. выше).
- **`[manual]`** — только то, что требует человека: решения, покупки, аккаунты, проверка с телефона. Задача останавливает автопилот в `waiting-user`.
- `[manual]`-задача содержит, что сделать, где (ссылки) и как понять, что всё ок. Ссылку, которой нет на момент планирования, дописывает в текст ручной задачи та задача, которая её создаёт (обычно «Финальный артефакт»).
- Отметка шагов `[manual]`-задачи — в пульте: чекбоксы у шагов в блоке «Ждёт вас» и во вкладке «План»; «Есть замечания» открывает чат с заготовкой и шаг не отмечает. Отмеченный шаг пишется в файл плана и коммитится в репозиторий проекта; после отметки последнего шага автопилот продолжит в течение минуты.
- Без пометки — обычная задача, которую выполняет автопилот.
- У каждой задачи должна быть хотя бы одна галочка (`- [ ]`).

### Очередь планов

Новый план попадает в очередь командой `node autopilot.mjs queue add <projectDir> <planPath>`. Автопилот берёт следующий план из очереди, когда текущий завершён или ждёт человека, и возвращается к ожидающему плану, как только в нём отмечена нужная задача. Срочный план ставят первым кнопкой «Запустить» во вкладке «План» или через `switch.json`. План, не попавший в очередь, автопилот сам не выполняет — не обещайте «переключится сам», если план не в очереди.

### Модель на задачу

- Пометка в конце заголовка задачи: `### Task N: Название · model: sonnet` (допустимо `haiku`, `sonnet`, `opus`).
- `haiku` — механика по готовым образцам и точным указаниям (данные, тексты, документация, скриншоты); `sonnet` — обычная разработка, когда план задаёт интерфейсы, тесты и значения; `opus` — сложная логика без готового решения, безопасность, ревью свежим ревьюером, исправления после ревью, всё, где ошибка дорогая.
- Пометку ставят каждой задаче, кроме `[manual]`; при сомнении — ступень выше. `[planner]` без пометки идёт на `opus`.
- При неудаче автопилот сам повышает модель (`haiku → sonnet → opus`); статистика по моделям — `node autopilot.mjs stats`.

## Команды

| Команда | Что делает |
|---|---|
| `node autopilot.mjs status` | статус, прогресс `x/N`, текущая и следующая задача, когда следующая попытка, причина остановки, последняя строка `APK:` из журнала прогресса |
| `node autopilot.mjs resume` | снять остановку (`done`/`halted`/`paused`/`waiting-user`/`auth`), сбросить счётчики попыток и запустить службу |
| `node autopilot.mjs once` | один шаг вручную |
| `node autopilot.mjs run` | цикл (так запускает systemd) |
| `node autopilot.mjs stats [--plan <файл плана>]` | сводка `logs/runs.jsonl` по моделям: запусков, задача закрыта, среднее время, стоимость, выходные токены; `--plan` — только запуски этого плана (по имени файла); повреждённые строки пропускаются («пропущено строк: N») |
| `node autopilot.mjs queue list` | очередь планов (`state/queue.json`): номер, проект, план, прогресс, отметка «ждёт вас: Task N» |
| `node autopilot.mjs queue add <projectDir> <planPath>` | добавить план в конец очереди; нет файла плана — ошибка; повтор не дублирует |
| `node autopilot.mjs queue up <n>` / `queue remove <n>` | поднять запись на одну позицию / убрать из очереди (номера из `queue list`) |

`status` при непустой очереди добавляет блоки «Очередь» и «Ждёт вас» (все `[manual]`-задачи планов очереди).

## Управление с телефона

При `"ntfyCommands": true` (и заданном `ntfyTopic`) служба `run` слушает канал команд `<ntfyTopic>-cmd` и отвечает уведомлением в основной канал. Распознаются только слова из списка (регистр и пробелы по краям не важны), всё прочее — ответ «неизвестная команда»; текст команды никуда не передаётся — ни в shell, ни в Claude.

| Команда | Что делает |
|---|---|
| `статус`, `status`, `?` | ответ: статус, прогресс `x/N`, текущая/следующая задача, следующая попытка |
| `пауза`, `pause`, `стоп`, `stop` | пауза; во время итерации Claude не прерывается — пауза наступает после текущей задачи |
| `продолжить`, `resume`, `дальше`, `go` | снять остановку (как `resume`) или не ждать конца паузы после лимита |

- С командами остановленный автопилот (`done`, `halted`, `paused`, …) не завершает процесс, а ждёт команд. Без `ntfyCommands` всё как раньше: остановка — выход.
- `state/commands.since` хранит id последней обработанной команды: после обрыва связи или перезапуска старые команды не выполняются повторно. Без файла подписка начинается с момента запуска.
- Если ntfy недоступен, автопилот работает дальше и переподключается раз в 5 → 60 с.
- **Кнопки.** С `"ntfyCommandToken": "tk_…"` уведомления получают кнопки («Продолжить», «Статус», «Пауза» — не больше трёх): нажатие отправляет команду в `<ntfyTopic>-cmd` с этим токеном. Токен виден всем, кто читает уведомления, поэтому давайте ему только право записи в канал команд.
- **Права на своём сервере ntfy:** телефону (токен кнопок) — запись в `<ntfyTopic>-cmd`; пользователю автопилота (`ntfyToken`) — запись в `<ntfyTopic>` и чтение `<ntfyTopic>-cmd`. Например, `ntfy access phone 'autopilot-*-cmd' write-only` и `ntfy access autopilot 'autopilot-*-cmd' read-only`.

## Пульт в браузере

Страница для телефона: `https://<хост>/pult/` (за тем же паролем, что веб-терминал `/term`).

- **Чат** — разговор с отдельной сессией Claude-планировщика: он читает и меняет планы проектов, ответ идёт потоком. «Стоп» прерывает ответ, «Новый разговор» в меню начинает новую сессию. Если телефон ушёл в фон, ответ всё равно дописывается и виден при возвращении.
- Картинки к сообщению (до 5) — через 📎 или, на компьютере, вставкой из буфера обмена (Ctrl+V в поле ввода, например скриншот).
- **План** — текущий план (`planPath`) с прогрессом `x/N`; нажатие на задачу раскрывает её текст.
- **Статус** — то же, что `node autopilot.mjs status`, и кнопки «Пауза» / «Продолжить»: они публикуют `пауза`/`продолжить` в `<ntfyTopic>-cmd` с `ntfyCommandToken`, исполняет их демон (нужен `"ntfyCommands": true`).
- С `"webPublicUrl": "https://<хост>/pult/"` в `config.json` нажатие на любое уведомление ntfy открывает пульт.

**Как устроено.** Служба `agent-autopilot-web` (`web/server.mjs`) слушает только `127.0.0.1:<webPort>` (по умолчанию 7690), своей авторизации у неё нет — её даёт Caddy (`handle_path /pult/*` с `basicauth`). Состояние — `state/web/` (`session.json`, `history.jsonl` — последние 500 записей).

**Установка** (наружу открывается новый путь, поэтому запускает человек):

```bash
bash /root/agent-autopilot/scripts/setup-web.sh
```

Скрипт ставит юнит `systemd/agent-autopilot-web.service`, добавляет в `/etc/caddy/Caddyfile` блок `/pult/` с хешем пароля из блока `/term` (резервная копия — `Caddyfile.bak-pult`), проверяет `caddy validate`, включает службу, перезагружает Caddy и проверяет curl'ом: без пароля 401, с паролем 200. Повторный запуск блок не дублирует. После установки впишите `webPublicUrl` в `config.json`.

**Правила планировщика** (`web/planner-prompt.md`): отвечает кратко; меняет только неотмеченные задачи; перед перестройкой задач, которые может выполнять автопилот, ставит его на паузу; изменения плана коммитит; новый план всегда заканчивается проверкой результата, ревью свежим ревьюером и финальным артефактом; шага `git push` в планы не добавляет; код проектов сам не пишет, если об этом прямо не попросили. Картинку (превью, скриншот) показывает в ответе: `node web/share-image.mjs <путь> "<подпись>"` копирует файл в `state/web/uploads/` (те же 8 МБ и 200 последних файлов, что у загрузок пульта) и печатает строку `![подпись](uploads/<id>)` — пульт рисует её миниатюрой.

## Запасная учётка

Если основная учётка Claude упёрлась в лимит (5-часовой или недельный), автопилот не спит до сброса, а сразу повторяет ту же задачу на запасной учётке. Попытка при этом не засчитывается. Когда основная сбросилась, автопилот возвращается на неё перед следующей задачей.

**Конфиг.** Поле `accounts` в `config.json` — список учёток по приоритету, первая — основная:

```json
"accounts": [
  { "name": "основная" },
  { "name": "запасная", "configDir": "/root/.claude-alt" }
]
```

`configDir` — каталог настроек Claude Code (`CLAUDE_CONFIG_DIR`) со своим входом. Учётка без `configDir` запускается как раньше, без `CLAUDE_CONFIG_DIR`. Без `accounts` или с одной записью всё работает как прежде.

**Переключение.**
- Лимит на учётке → её время сброса записывается (из сообщения о лимите, иначе «сейчас + `retryMinutes`») и задача повторяется на следующей учётке без лимита.
- Все учётки в лимите → одно состояние `sleeping` до ближайшего сброса.
- Перед каждой задачей: если учётка с более высоким приоритетом уже без лимита, автопилот возвращается на неё. Возврат бывает только между задачами.
- Каждое переключение — одно уведомление ntfy и одна строка в `logs/autopilot.log`: «Лимит «основная» до …, продолжаю на «запасная»» или «Вернулся на «основная»».
- Если на запасной нет входа, она отмечается как недоступная до `resume`, и приходит уведомление «Запасная учётка не авторизована». Если основная при этом в лимите, автопилот ждёт её сброса, а не останавливается с `auth`.

**Установка запасной.** Скрипт создаёт каталог `/root/.claude-alt`: симлинки на `settings.json`, `plugins`, `skills` и `projects` из `/root/.claude`, так что плагины, навыки и память общие. Файл `.credentials.json` скрипт не трогает. Повторный запуск безопасен. Если в каталоге уже лежит не симлинк, скрипт сообщает об ошибке и ничего не меняет.

```bash
bash scripts/setup-alt-account.sh
CLAUDE_CONFIG_DIR=/root/.claude-alt claude   # затем в сессии: /login
```

Вход — отдельный ручной шаг: логиньтесь под той учёткой, которую хотите сделать запасной. Проверка: `CLAUDE_CONFIG_DIR=/root/.claude-alt claude -p "ответь ок"` печатает ответ.

**Статус.** `node autopilot.mjs status` при двух и более учётках добавляет строки `Учётка: <имя>` (текущая) и `Лимит: <имя> до <время>` для каждой учётки, которая ещё в лимите.

**Пульт.** Блок лимитов показывает по одной карточке на учётку; активная помечена «— активная». Если у запасной нет `.credentials.json`, в её карточке выводится ошибка, а остальные лимиты показываются. Чат пульта работает на текущей учётке из `state.json`.

Известное: метка активной учётки в блоке лимитов пульта кешируется на 60 секунд, поэтому после переключения она может отставать на минуту.

## Codex — исполнитель

Обычные задачи планов может выполнять OpenAI Codex CLI (`codex exec`, подписка ChatGPT Plus), а Claude остаётся «головой»: планировщик в пульте (чат), задачи `[planner]` и запасной исполнитель.

- **Кто что делает.** Чат пульта и задачи `[planner]` — всегда Claude. Обычная задача при `"executor": "codex"` — Codex. Если Codex в лимите или не авторизован, задачу берёт Claude по приоритету учёток; попытка при этом не засчитывается.
- **Конфиг.** `"executor": "codex"` в `config.json`; без этого поля или с `"claude"` всё работает как раньше. Учётка Codex — запись в `accounts` с `"kind": "codex"` и `"codexHome"` (каталог с `auth.json`, обычно `/root/.codex`). Учётки Claude в том же списке остаются, у них `kind` по умолчанию `claude`.
- **Модели.** `codexModels` переводит пометки `haiku | sonnet | opus` в модель и уровень рассуждений Codex: `{ "sonnet": { "model": "<модель>", "effort": "medium" } }`. Допустимые `effort`: `minimal | low | medium | high | xhigh`. Идентификаторы моделей автопилот не проверяет — берите их из своей версии Codex. Записи нет — Codex запускается со своей моделью по умолчанию. Эскалация `haiku → sonnet → opus` работает как для Claude.
- **Вход.** `codex login --device-auth` (код устройства, вход под аккаунтом ChatGPT с подпиской Plus). Проверка: `codex exec --json "ответь ок" < /dev/null` печатает ответ. Без `< /dev/null` `codex exec` ждёт ввода из stdin.
- **Выбор и возврат.** Перед каждой задачей: если Codex в лимите или без входа, задачу делает Claude; возврат на Codex — перед следующей задачей после сброса его лимита. Переключение происходит только между задачами.
- **Уведомления.** На каждое переключение одно сообщение ntfy: «Лимит Codex до …, задачу делает Claude», «Codex не авторизован, задачу делает Claude (вход: codex login --device-auth)», «Вернулся на Codex». Строка в `logs/autopilot.log` — та же, с именем исполнителя в строке запуска: `run Task N (codex/sonnet, попытка 1)`.
- **Лимиты.** Codex считает два окна — 5-часовое и недельное. Проценты и время сброса берутся из последнего события `rate_limits` в `$CODEX_HOME/sessions/**/*.jsonl`. В пульте — отдельная карточка учётки Codex; в `status` — строка `Исполнитель: codex (5 ч: N %, неделя: M %)`. Нет каталога сессий или событий — показывается «нет данных».
- **Статистика.** `node autopilot.mjs stats` разбивает запуски по исполнителю и модели: `codex/sonnet`, `claude/opus` и т. д.
- **Права.** Codex запускается без запросов подтверждений и без песочницы, в каталоге `projectDir`. Это значит, что агент может читать и файлы учёток Claude и Codex, в том числе токены. Токены не попадают в лог, уведомления и пульт.

## Проекты и переключение

- **Один конфиг на все проекты.** Общие настройки (ntfy, лимиты, `stateDir`) — в одном `config.json`; проекты — в его списке `projects`, отдельные `config.<проект>.json` не нужны. Переключение между проектами и планами — кнопка «Запустить» во вкладке «План» пульта (или `switch.json`, см. ниже).
- **Список проектов** — необязательное поле `projects` в `config.json`: `[{ "name": "…", "projectDir": "/abs/path", "plansDir": "docs/plans", "progressPath"?: "…" }]`. Планы проекта — все `*.md` в `plansDir` (без подпапок), кроме `*.progress.md` и `progressPath`; журнал плана без своего `progressPath` — `<план>.progress.md`. Без `projects` проект один — из `projectDir`/`planPath`/`progressPath`.
- **Активный план** — `state/active.json` (`{ projectDir, planPath, progressPath }`, пути — как в `config.json`). Если файл есть, он перекрывает эти три поля конфига для `run`, `once` и `status`; нет файла — работает как раньше.
- **Переключение** — запрос `state/switch.json` того же формата (его пишет пульт; новый запрос заменяет прежний). Демон берёт его только между задачами: текущая задача доходит до конца на старом плане, затем демон пишет `active.json`, сбрасывает состояние и счётчики попыток (`state.json` → `idle`), отменяет отложенную паузу и шлёт уведомление «Переключено: <проект> / <план>». Если автопилот остановлен (`done`/`paused`/`halted`/…) или ждёт сброса лимита, переключение происходит в течение секунды — но только при `"ntfyCommands": true`: без команд остановленный демон завершается, и запрос применится при следующем `run`.

## Логи

- `logs/autopilot.log` — по строке на событие.
- `logs/iter-<время>-<задача>.log` — полный вывод каждой итерации Claude.
- `logs/runs.jsonl` — по строке JSON на каждый запуск Claude, включая неудачные: `{ at, project, plan, task, title, model, attempt, result, done, durationSec, tokens, costUsd }`. `model` — `null`, если `--model` не передавался; `tokens`/`costUsd` — `null`, если Claude не напечатал JSON-результат (таймаут, ошибка запуска). Сводка — `node autopilot.mjs stats`.
- `journalctl -u agent-autopilot` — вывод службы.
- `state/state.json` — текущее состояние.

## Что делать, если остановился

- **`waiting-user`** — сделайте ручную задачу, отметьте её галочки, затем `resume`.
- **`halted`** — посмотрите последние `logs/iter-*.log` и журнал прогресса проекта (строки `НЕ СДЕЛАНО`), поправьте план или окружение, затем `resume`.
- **`auth`** — запустите `claude`, выполните `/login`, затем `resume`.
- **`paused`** — проверьте результат этапа, затем `resume`.

## Права

Итерации идут с `--permission-mode dontAsk --settings claude-settings.json`: разрешено всё из списка в `claude-settings.json`, остальное запрещено без вопросов. `--dangerously-skip-permissions` под root Claude Code не запускает.
